# 竞技场策略兼容接口（非人类玩家界面）

人类玩家的竞技场默认 `manual`，匹配面板不提供策略选择。普通自动战斗由玩家主动开启，
不依赖竞技场策略参数。AI 玩家及其策略产品尚未安排；下文仅记录已有本地兼容接口。
已有显式保存的策略选择继续保留。通过兼容接口选择自动策略后，准备、排队、倒计时与战斗期间客户端持有一个竞技场专用循环；实际出招还要求比赛 ID、
竞技场阶段及正常战斗的回合状态全部匹配。它不移动角色，也不回答普通战斗。

| 策略 | 行为 |
| --- | --- |
| `basic` | 复用基础自动战斗规则：优先治疗，攻击存活目标，宠物使用默认技能；不逃跑。治疗需本地恢复数据表，未配置时仍可攻击。 |
| `manual` | 停止内置自动出招，使用 Web 战斗操作或 sactl 的正常战斗指令；本地脚本也选择此模式。 |
| 本地扩展 ID | 由运行客户端的本地代码注册，分类为 `intermediate` 或 `advanced`；当前未附带这两类的成品策略。 |

选择保存在服务端 SQLite 的 `ladder_preference`，按持久角色 ID 隔离。重连、下一场比赛
与服务器重启后保留选择，包括 `manual`。`sactl arena strategies` 返回当前客户端已安装
策略的结构化元数据；`arena status` 的 `data.snapshot.self.strategy` 返回当前选择。
如果换客户端后扩展未安装，不能静默回退到初级策略，需明确选择已安装策略或手动。

切换策略不会撤销或重复本回合已接受的动作。`auto-battle off` 在竞技场占用期间也向服务端
请求切到 `manual`。Web“接管”先停止本地循环，再确认服务端选择；若回执未知，返回最新
控制版本和完整原请求，面板保留待重试请求，避免把停止成功误显示成仍被自动控制。

Web 的类型化竞技场 HTTP 接口负责启动 Web 策略；原始游戏协议报文不会启动桥接端策略。
因此 sactl 经 HTTP 传输时仍由自身 daemon 出招，不会再启动一个 Web 循环。普通原地
自动战斗已经运行时可复用该循环，但自动寻敌必须先停止才能准备或排队。

## 本地扩展契约

公共接口在 `internal/battleauto/strategy.go`：实现 `Strategy.Info()` 和
`Strategy.Decide(context.Context, aigame.Snapshot) (Decision, bool, error)`，通过宿主
`Config.LadderStrategies` 在本地编译/嵌入时注册。此字段不从 sactl TOML/JSON 配置加载，
也没有网络上传、任意进程启动或大模型入口。

- 元数据 ID 为 1–32 位小写字母、数字、下划线或短横线，不得重复或覆盖内置策略；
  名称非空，等级为 `intermediate` 或 `advanced`。元数据应保持不变。
- 输入是共享层的游戏快照，含回合、人物/宠物指令是否已提交、可观察参战信息及竞技场状态；
  没有 socket、凭据或修改服务端结果的接口。不得猜测协议未提供的能力或隐藏数据。
- 返回 `ready=false` 表示本次不提交；`ready=true` 只允许 `ActionBattle`。命令合法性、
  控制版本、观察版本和回合就绪状态由宿主与公共执行层再次验证。
- 每次决策提供最多 500ms 的协作式截止时间。扩展必须响应取消并及时返回；本地扩展是
  受信任代码，宿主不会强制终止忽略取消的 Go 函数。过期或取消后的返回值不会提交。
- 策略不负责重试未知结果、不自行连接、不创建后台出招循环。多角色共用注册实例时，
  扩展必须允许并发调用；按角色/比赛管理的临时状态不得串到其他角色。

初级策略、扩展动作边界、取消、手动接管、循环更替、HTTP 单一策略宿主和偏好持久化
已有专项测试。浏览器策略选择器用协议快照夹具检查过手机和桌面布局；这些证据不代表
真实认证连接上的完整 Web/sactl 竞技场流程已经验收。

中高级扩展另已验证两端宿主注册、选择、运行和手动接管：Web 从 HTTP 操作到 TCP
原生防御指令，sactl 从命令处理器到 daemon 循环提交防御动作。两类元数据分别验证，
公共层及两端宿主的全包 race 检查通过。这些测试使用本地测试策略，不能替代自定义
策略本身的行为验证。记录为 `build/ladder/local-strategy-host-race.log`。

sactl 初级策略另已通过真实网关认证后的同场重连检查：daemon 退出后重新登录，不再
设置策略即可自动回答下一回合的人物和宠物指令，并完成原场结算。该证据来自双人比赛，
不代表 Web 或多人重连已验收。记录见 [实现跟踪](arena-implementation.md)。
