# 2026-10-02 Web 程序 CDN 资源缺失

线上首页已恢复。此次故障的直接原因是：生产切换到 v0.2.13 后，HTML 引用了新的内容哈希目录，但该目录的程序资源未随部署就位；发布验收又只检查了服务健康和下载区，未检查实际游戏页面的 CSS/JavaScript。

## 原因与证据

| 核查项 | 结果 |
| --- | --- |
| 上一个线上版本 v0.2.9 | 使用 `web/0352520f698a20c7f08657e2a9e83ee76cc2f211ca8b76cd500a95458833b0f8/`；故障调查时其 CSS、JavaScript 仍为 HTTP 200，SHA-256 与该 tag 源码生成的字节一致；Last-Modified 为 2026-09-29 04:38:01 UTC。 |
| v0.2.13 的 Web 变更 | 提交 `294aa7e21` 修改了 `client/web/runtimeassets/index.html` 的宠物技能容量、状态解析和动作规则等逻辑；因此嵌入脚本内容及整组资源哈希发生变化。此次变更虽以 sactl/AI 为主要工作，实际也包含 Web 程序变更。 |
| 新目录 | v0.2.13 使用 `web/3278d821acf75d760981dc4fc77a0f2652a6a74517c6f5035ca519213bea6910/`。部署当时保留的 `home.html` 已引用它；本次修复前，其 app.css 和 app.js 均返回 OSS `NoSuchKey` / HTTP 404。 |
| 部署记录 | `build/release-v0.2.13/deploy.log` 显示校验 Compose、使用已有镜像后直接启动容器，没有 `sync-assets` 或 Web 资源发布步骤。Web 容器创建于 2026-10-02 03:36:18 UTC。 |
| 验收遗漏 | 当时 `production-verification.json` 只记录六个健康容器、镜像摘要、健康接口、服务列表和百科下载入口，没有目标 Web 目录的 GET/摘要核验或新浏览器游戏页面验收。HTML 返回 200 被错误地当成了网页可用的充分证据。 |
| 后续 sactl 发布 | v0.2.13～v0.2.16 的嵌入 Web 资源没有变化，生成的目录相同；`publishSactlPackages` 仅写入 `downloads/sactl/`，不删除 Web 目录，也不会补发游戏 Web 程序资源。 |

旧资源并未整体消失：旧目录仍可读取，故障页面引用的是另一个新目录。现有发布日志、保留 HTML、Git 源码及实际 HTTP 响应共同定位到新版本资源发布遗漏。未取得 OSS 历史对象操作审计，因此不将任何未知的历史对象事件描述为已完成审计排除。

## 恢复过程及伴随问题

通过生产已发布版本的项目入口 `bin/stoneage sync-assets --web-only` 恢复程序资源，未重启游戏服务。

第一次恢复尝试被输入一致性检查拒绝：服务器 `assets/sprites/manifest.json` 为 4,749,017 字节，SHA-256 为 `cea89b41bdf756c0a0461ba0117ec2e8d7f3f8f1d986ca02e2fe3167d2120f45`；CDN 已发布版本为 4,833,216 字节，SHA-256 为 `7467b9451ad1ec6c09525f1e99165085d3078ed49df1c9e376c3e63666f8f827`。服务器本地文件修改时间为 2026-09-19，早于本次发版。这是恢复时发现的既有输入不一致，不能据此推定此前曾经运行同步并失败。

保留生产原始文件，在独立恢复输入目录中使用现有一致索引与 CDN 的 manifest.json，核验其大小及 SHA-256 与 `_client-manifest.json` 一致后，再通过同一个项目入口执行 Web 同步。没有强行覆盖游戏图片，也没有改写任何摘要。

同步成功后，程序目录与线上 HTML 一致；游戏资源版本仍为 `2f72a796d24e2ae1b7380fba39ff82872c905f269688aaecb5aef0ee4b7ef29b`。恢复后的 app.js Last-Modified 为 2026-10-02 06:27:32 UTC（北京时间 14:27:32）。首次直接观测到缺失是在北京时间 14:22；未保留持续探测数据，不能把整个风险窗口描述成逐分钟核实的停用时间。

## 恢复验收

- 从实际 CDN 域名获取目标目录的全部 13 个程序对象，均为 HTTP 200，内容摘要逐项匹配 v0.2.13 源码。
- 浏览器实际呈现完整登录背景、样式和输入控件；未观察到资源加载失败或脚本错误。未使用用户账号登录或执行游戏操作。
- 生产镜像保持 v0.2.13，服务未重启。
- 原始证据保存在本地 `build/website-runtime-history.json`、`build/website-cdn-verified.json`、故障/恢复截图及 HTTP 头中；原发布日志和验收记录保留，不追改为“当时验证通过”。

## 发布要求

强制要求已加入 [AGENTS.md](../../AGENTS.md) 的“CDN 资源是发布的强制前置条件”：先发布并逐对象验证目标 tag 的 CDN 资源，再切换生产镜像；发布后以新浏览器实际加载验证。容器健康、HTML 200 或下载区正常均不能替代此验收。相关操作顺序见 [部署说明](../docker-compose.md#cdn-程序资源发布v0172-起)。

当前 `bin/deploy.sh` 仍只自动检查 Compose 与容器健康；本次修改的是强制操作规则和验收要求，不能声称自动部署拦截已实现。
