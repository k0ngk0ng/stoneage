# 可视化玩家管理实现与验收

目标：管理员从账号选择具体角色，查看并修改当前拥有的宠物、宠物技能、装备、物品、金钱及角色属性。赠送目录可按名字、编号、描述搜索，并使用 client/web 同一套原始资源展示外观。包含随身与仓库；同时处理在线与离线角色。

## 实现分工

- `internal/playerdata`：2.5 SAAC 存档封装、角色/宠物/物品嵌套格式，保留未修改字段与 CP936 字节，版本指纹和界面数据结构。
- `internal/gamecatalog`：运行时宠物、物品、技能目录，服务端真实模板编号和图形编号，搜索。
- SAAC 主循环桥：列出角色、读取存档，未在线且预期存档完全匹配时原子写入。后台不直接覆盖存档。
- GMSV 主循环桥：在线状态快照、原生赠送/修改/删除、刷新和保存；离线赠送也须复用原生物品/宠物初始化规则。
- 后台服务：认证、CSRF、账号与角色绑定、参数验证、请求去重、冲突处理和可追溯审计，连接两个游戏服务桥。
- 后台页面：账号下角色选择；钱与属性、装备、背包、仓库、宠物、技能的可视化编辑；搜索与赠送确认；明确失败和冲突。
- 外观：解析 Web 使用的位图/精灵清单与逻辑图形别名，宠物选择站立动作，物品展示真实图标；缺资源时明确显示缺失。

- [x] 宠物、物品、宠物技能可搜索，名称与原始模板 ID 对应正确。
- [x] 宠物和物品外观与 client/web 相同，无图/加载失败可识别。
- [x] 赠送宠物/物品使用原生初始化规则，数量与库存满处理准确。
- [x] 修改/删除已有宠物、物品，设置/删除宠物技能，钱与属性修改均落盘。
- [x] 在线修改刷新客户端并正确保存，战斗/交易等冲突明确拒绝。
- [x] 离线修改与登录互斥；重新登录/保存后修改不丢失。
- [x] 同时操作、旧快照、重复提交不会覆盖新数据或重复赠送。
- [x] 权限、CSRF、账号/角色绑定、路径及输入限制、审计均经过测试。
- [x] 真实中文存档不损坏，未知字段保留，容量和边界正确。
- [x] 桥协议和 C 行为有真实格式/运行测试，Go 与页面有对应集成测试。
- [x] 浏览器实际检查搜索、预览、赠送、编辑、错误与移动端布局。
