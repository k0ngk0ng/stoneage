# learned v2 初始特征与轨迹契约

当前代码：`internal/battlepolicy`、`internal/battletrain`。这是受控攻击/防御/破防/状态攻击/治疗/有限消耗品场景的初始实现；在线 learned 接入、扩充动作、训练工具产品化和胜率验收仍在进行。完整目标见 [设计](learned-strategy-design.md)，落地范围见 [实现记录](learned-implementation.md)。

## 可见性和输入边界

`Encode` 只接受一方完整队伍的 `[]aigame.BattleView`，校验比赛、回合、模式、阵营、规则兼容号、己方槽位唯一、参战列表一致、人物尚未提交。在场成员要求菜单就绪；已被击飞移出的成员要求本回合完整观战快照、`withdrawn=true` 且无候选动作。多人缺少一个成员就返回错误，由上层明确处理，不偷偷按单人策略决策。

`withdrawn` 来自公共竞技场完整 BC 表中原人物槽位缺席；不能用 HP=0、超时或缺少网络事件代替。每次竞技场 BP 后须等待新的完整 BC，截断或重复槽位的 BC 不确立新观察。服务端保留离场成员的 BP/BC/BVS/BA 及后续电影广播直至结算；刚被击飞的回合已有原生电影，不再重复发送。该行为同时用于 Web、sactl 和离线引擎。

仍在 BC 中的倒下人物另行处理：完整观察须同时证明死亡且 HP=0、人物菜单关闭、BA 已确认该人物行动、本回合没有本地提交，才能接受其 `PlayerSubmitted` 状态。人物继续参与实体编码，但不再生成重复人物指令；其存活宠物仍独立规划。`completed_players` 是可选的成员路由元数据，不进入网络数值特征；既有合法输入的特征和动作含义不变。存活人物的部分提交、已提交的宠物以及本地预留动作仍不得重新推理替换，须恢复已有最终计划。

己方所有成员可共享私人状态；敌方只使用 `Battle.Participants` 公开字段。姓名、稳定身份、场次、观察 ID、技能/槽位 ID 的数值大小不进入网络。字段中的 ID 只供关联、固定词表查找、分组和提交；人物/宠物在战场中的位置是有意义的输入，按己方在前、敌方在后归一化。成员输入顺序、绝对阵营编号不改变同一个场景的数值决策。

来源与缺失：

| 输入 | 公共解析来源 | 初始使用规则 |

`CombatStatsKnown=false` 时对应值列和 known 列一起归零，未知和真实零靠 known 区分。完整状态建立标记，选角、宠物替换、不完整或格式错误的数值更新会使标记失效。仅 `HasStatus=true` 不足以证明属性齐全。宠物 MP 是原始协议保留观察，不表示增加了宠物气力机制。

宠物容量限制复用公共 `BattleSkillIndexAllowed`，用于候选和 CLI/结构化 Web action；浏览器菜单、上回合动作和点击前检查使用同一原生条件，经真实 K 报文与原生执行结果交叉验证。普通 Web 原始 `/send` 是既有报文转发通道，最终仍由服务端校验，不声称其经过所有 typed action 检查。完整 K/身份替换清除旧容量和技能证据；名字先分字段再反转义。新增宠物忠诚及四元素的原始投影尚未作为新的模型特征输入，不能把字段存在等同于模型已使用。

## 数值布局

新建模型 schema：`commander-observed-v8`，动作词表为 `attack-guard-switch-guardian-v7`；v6/v7 模型继续使用 `attack-guard-switch-v6`。保留 v3 的成员→实体行映射与离场后变长联合计划，v4 新增有序公开效果，v5 增加消耗品，v6 加入备用宠物和换宠；v7 使用已确认的承伤者并增加保护者位置。网络配置 `input_schema` 将特征含义绑定到模型摘要；既有 v6 配置省略该字段，保持原字节及摘要，明确按 v6 编码。当前兼容 v6/v7/v8，其他旧版本不猜测迁移。v8 增加忠犬候选及宠物技能证据，要求 `controlled-battle-v8` 校验实际技能函数、目标类型与参数；v7/v8 的历史编码相同。模型 manifest、网络配置、checkpoint、轨迹和推理帧必须一致，不得重标旧权重。

通用绝对数值使用有符号 `log(1+abs(x))/log(1001)`；比例裁到 0～1，分母未知时置零。这个缩放固定，不读取验证/测试数据拟合统计量。

技能词表映射受控环境的宠物技能 1、2、3、60、80、90、110。后四项通过原生技能表的处理函数、目标类型、战斗可用标记及选项字节共同校验，不能仅凭 ID 猜效果。持续时间输入是技能表中的名义参数，不是对敌方剩余控制回合的透视；实际触发及持续仍由原生引擎结算。治疗魔法覆盖人物魔法 ID 10、20，分别要求存活的单体目标或存在存活实体的整侧目标；ID 必须由本角色 J 报文明确提供，原生环境核对实际处理函数、范围、目标、费用及参数。候选的 MP 消耗来自同一报文，不从旧装备缓存拼接。其他魔法、其他物品和其他技能暂时保留在候选数据中，以 `Supported=false` 排除，`Excluded` 显示排除数量。没有任何已覆盖动作的行动者直接报错。这个掩码表示模型覆盖范围，不能用它宣称整个比赛场景已覆盖；在线适用性和回退仍需模型 manifest/上层检查。

治疗道具目前只覆盖模板 1234（小块肉）。原生创建时验证真实 ID、ITEM_useRecovery、参数体20、使用范围、目标和等级；不按名称猜测。`S:I` 先更新背包、使旧身份失效，再由本角色的 `S:AI` 确认模板；候选携带 `item_template_id/item_template_id_known`。`inventory_known` 来自有效 AI 物品列表，只有全部相关背包槽身份已知才编码库存；未知与确认用完不同。已占用槽代表可消耗的物品对象，不虚构未提供的堆叠数量。当前原生 `_CHAR_DelItem` 消耗整个槽中的物品。候选只允许存活单体目标，含己方、敌方和宠物；名义恢复量 20 不保证实际恢复恰好 20，随机、状态和 HP 上限仍由引擎处理。背包普通 Web 界面不显示新增内部编号。

## 历史与联合计划

每队固定选择己方最小人物战场槽位作为历史观察者；不拼接所有成员相同的广播。批次必须绑定该成员本次 observation ID，事件 sequence 严格递增、不得超过 cursor；缺失、轮转或断裂显式标记。真实流最初可能包含上一场尾部，序列仍计入截点，但其效果不进入新比赛。

该成员被击飞后继续接收公共电影和完整观战快照，保持同一历史流；不会在模型内部拼接另一个成员的 sequence。`Frame.members` 按调用方成员顺序记录其实体行，离场成员为 -1；所有在场己方人物必须被映射。联合计划省略离场成员及其已移出的宠物，`Selections` 为这些成员返回空列表；不把无效的 N 指令算成一次模型选择或策略概率因子。

历史输入宽度为 128。每次决策先按报文 sequence、再按该报文 Effects 原始顺序读取效果 token，最后读取一个回合汇总 token。所有 token 使用同一个历史 GRU；每次决策只计算一次当前战场注意力，当前已知战场表示作为各历史步的共同上下文，不冒充每个效果发生时的中间快照。跨回合继续上一决策记忆，重放从相同起点得到相同结果。

汇总 token 的前 16 列沿用：己/敌攻击次数、己/敌防御次数、己/敌 HP 变化、己/敌 MP 变化、己/敌状态变化次数、未知效果次数、效果总数、历史缺口、初始回合、己/敌反击次数；16～21 为己/敌等待、收宠、召唤次数；22～126 为零，127 为 1。前 12 列及反击/等待/收宠/召唤次数使用上述有符号对数缩放。v6 固定将反射/守护承伤计入未知，不错误累计到原目标；公共 journal 后来补充的 recipient/guardian 不改变已有模型和轨迹的数据契约。

v7 的攻击/反击按 `recipient` 累加实际作用阵营，吸收为正，普通伤害为负；无 recipient 或槽位无效时计入未知，不能退回原目标猜测。闪避/无效化保留已知零伤害，不虚构承伤位置。其他效果、计数和历史截点规则不变。

效果 token 布局（127 为 0）：

| 列 | 含义 |
| --- | --- |
| 0～7 | 攻击、反击、HP 变化、MP 变化、状态、防御、未解析/部分未知、等待 |
| 8～13 | 行动者、原目标、实际受影响者、HP 变化、MP 变化、状态已知 |
| 14～15 | 公共日志段序号和总段数，对数缩放；不作为服务端时间 |
| 16～35 / 36～55 / 56～75 | 行动者 / 原目标 / 已确认受影响者的 20 槽 one-hot，按己方在前归一化 |
| 76～79 | HP 变化、MP 变化、已解析攻击的骑宠 HP 变化及其 known；数值对数缩放 |
| 80～95 | 攻击 Flags 低 16 位，各自编码 |
| 96～103 | 状态解除、中毒、麻痹、睡眠、石化、酒醉、混乱、其他，分类而非连续数值 |
| 104～105 | 收宠、召唤事件标记 |
| 106～125 | v7 保护者的 20 槽 one-hot，按己方在前归一化；v6 为零 |
| 126 | v7 保护者已知；v6 为零 |

槽位采用稳定战场位置，已离场者仍可在此前效果里被引用，不强行映射到当前剩余实体行。未知效果保留在序列原位，但不会从默认 Actor=0、文字或 Raw 推断行动者。原生 bn（等待）和 BS（收宠/召唤）按固定字段数解析；召唤的名字即使是 FF/BE 也不会被误当分隔符或指令。收宠/召唤的行动者是主人，目标是该主人对应的场上宠物位置；不从事件推测隐藏的持有槽位或身份。原生普通 BJ 的 FF 只结束该魔法头，后续 BD/BM/bg 按固定字段长度解析，保留同条报文后续治疗、状态和攻击；扩展未知魔法尾部仍保守处理，避免把十六进制 BE/FF 等数值误当指令。BD 的恢复量是电影报告值，可能大于实际因 HP 上限截取的恢复量；当前 HP 以新观察为准，不用电影值替代快照。伤害/恢复的资源重复报文由公共 journal 去重，模型不再自行解析第二套协议。

公共 journal 和 battle-events 提供可选 recipient/guardian（战场槽位 0～19）。普通命中指向目标，保护指向保护者，反射优先指向该次攻击者；闪避/无效化或对应身份未确认时 recipient 缺失，吸收仍由 flags 表示正向恢复。v7 编码采用这些字段；v6 保留原目标及 flags，继续按原契约忽略新增字段。升级模型输入需独立训练/评估，不能静默改变现存权重或轨迹。v8 已加入 20 号忠犬攻击候选；反射施法、骑宠独立伤害及其他特殊技能仍未全部覆盖。

每决策最多 512 个效果，超限明确拒绝并由上层记录失败/回退，不截掉开头或末尾冒充完整历史。仅使用观察游标以内的效果，不按服务端时间戳或展示回合重新排序。该表示保留已解析公开效果的先后；未知技能内部机制、精确时间和完整状态持续时间仍未知，不能声称已覆盖全部战斗语义。

计划按己方人物槽位升序、人物后接本人宠物依次产生，所有行动者共用一个网络。每步读取全场、回合记忆、已规划前缀。采样、贪心、强制动作概率重算使用同一个 `Forward`。返回各条件 log probability 及其和；整队 PPO 使用后者。`Selections` 只生成候选引用，实际指令仍由公共 resolver 校验和执行。

## 可选的 target-counts-v1 计划输入

此为网络计划契约，不更改 v6/v7/v8 的公共观察 frame、历史编码或动作候选。`network.config.plan_features=target-counts-v1` 对应 commander-policy-v3；结合 member scope 对应 independent-member-policy-v2。省略字段完全保留旧网络，不能手改旧模型标签。

每个待评分候选生成八列：此前可见计划条数、相同个体目标条数、相同目标物理攻击条数、毒/石化/混乱/睡眠各自条数、与此候选目标范围重叠的治疗条数。全部按实际整数计数除以 10；最多十个行动槽，评分时至多九个前序选择。异常攻击也计入物理攻击，破防同样计入；各列可以重叠。仅统计本次决策中此前已经选出的候选，不读当前或未来强制选择，不读敌方计划或结果。

相同个体目标只通过关联行相等判断，`-1` 不代表所有无目标/群体指令指向同一实体。治疗包括单体、道具和群体：按当前公开存活、阵营及非备用实体范围判断是否重叠，群体与群体按同一阵营匹配；对敌方施放仍按实际敌方目标计数。计数不是恢复量、命中率或已生效状态，不能代替下一回合观察。member scope 完全排除其他成员当前计划，但保留同样的公共战场信息。

八列经新增零初始化的 `score.plan.w`（8 × width）投影后，加到动作评分 MLP 的第一层激活前；历史 GRU、价值头、候选 mask、计划 GRU 的输入均不因计数而改变。采样、贪心和 teacher-forced/PPO 重算共享同一计算，梯度不穿过离散已选索引，保持原自回归语义。新模型需要独立训练及验证，不内置“不能重复石化”等规则。

## 数据与训练约束

`commander-trajectory-v2` 包含实际客户端观察、历史 batch、编码后 frame、覆盖 mask、联合选择及各条件概率、旧价值、终局奖励和最终观察。采集双方先决策再统一结算，不能读到对手尚未公开的动作。每个模型在采集期间固定；任何缺口、无可靠 successor 的截断、模型变化或不确定执行使该局采集失败。

真正终局不 bootstrap；采集回合上限有有效下一观察才 bootstrap，不能按平局标记。胜 +1、负 -1、引擎真正平局 0；其他回合奖励 0。双方视角共享实验家族 group，重复和换边的分组由编排者指定，后续划分必须整组处理。

每个轨迹校验时从保存的观察/事件重新编码，核对 frame 完全一致；PPO 另外用行为模型从第一回合起重放记忆，核对旧动作概率、价值和截断 bootstrap。拒绝其他模型的旧轨迹、规则/贪心轨迹、重复轨迹、混合规则/平台/模式。训练按连续片段反传；每轮先用当前权重重算整场前缀记忆，然后在片段边界停止梯度。当前实现整批累计后做一次 Adam 更新，失败不更改输入模型和优化器。

`commander-shard-v2` 以 SHA-256 命名不可变 gzip JSONL，manifest 记录压缩摘要、字节数、轨迹数、队伍回合数、group、模型和规则摘要。先完成并同步分片，再发布 manifest；读取验证摘要、长度和记录内容，遇到损坏拒绝覆盖。引擎握手报告包装脚本重新计算的程序/选定表/数值参数摘要及平台；采集必须匹配该元数据。轨迹保存完整初始配置和 seed，group 自动规范化初始条件并忽略 seed/换边/采集上限。规则覆盖清单和完整竞技场差分仍未审核完，不可把摘要字段存在视为规则一致性已经认证。

## v6 换宠与备用行

召唤候选的 Target 指向该成员对应持有槽位的备用实体行；收宠指向当前场上宠物行（已不在表中时为 -1）。这些行索引仅用于关联，持有槽位大小不作为网络强弱数值。备用行带显式标记和主人位置，具有已确认的 HP、等级、战斗属性和观察到的技能；不产生任何 Slot。群体治疗计数和 HP 比例排除全部备用行。

同回合计划仍先人物、再原出战宠物；S 提交后直到原生结算前不重写出战选择，不为刚召唤的宠物补一条指令。最初 v6 场景每个成员只配置一只宠物，可采样收宠与再次召唤；后续 v7/v8 场景加入下面的备用多宠和技能组合，强度仍须单独验收。网络架构及维度未扩大（197,954 参数），但语义升级须重新训练，不能重标旧权重。

## 多备用宠物受控场景

v7 场景增加 `--reserve-pets 0..2`，默认 0；用于新建 train、experiment、evaluate、build-search。每人额外携带指定数量的备用宠物，双方数量一致，每只宠物独立满足 `--pet-points` 预算；最多三只可选宠物，符合原生 SPET 限制。初始宠物保留七个已核实技能，随机备用宠物拥有攻击、防御及一种破防/状态技能，按槽位压紧排列。模型通过公开观察读取各宠物属性与技能，编号掩码只作场景元数据，不作为连续数值输入。配点搜索同时搜索备用宠物配点和专长技能，冻结实验、配点池、评估及断点恢复均保留完整阵容，不允许覆盖 reserve-pets。需新建 v7 实验；特征/动作契约仍为 v6，旧场景产物不可改标签复用。真实多宠切换和采样训练已验证，少量对局不代表学会有效的换宠战术。

## v8 忠犬与技能组合

实体列 55 在 v8 中表示公开可用的忠犬技能，v6/v7 仍为零；56～62 的原七技能及 63 的技能证据标记不变。候选的 Target 仍是攻击对象，保护对象固定为宠物主人，由关联位置查找其已知 HP，不能把主人替换成攻击目标。忠犬的原生参数为 `攻%-20 COM:攻击`；会攻击并为主人登记保护，当回合结束后清除，不保证命中或承伤成功。原生 `COM:防御` 属于不同语义，不冒充本技能。

`--pet-skills` 在 train、experiment、evaluate、build-search 中指定主宠技能集合，支持 1、2、3、60、80、90、110、20，最多七项且不重复。编号仅用于配置和词表查找，不作为连续强弱特征。显式配置要求 v8 场景；省略时保留原七技能。备用宠物保持攻击、防御及从主宠集合选出的一个专长；主宠没有专长时备用宠物仅有攻击、防御。场景底层另保存每只主宠的 mask 和备用技能 mask；按固定词表顺序压紧到实际技能槽，不扩容。

模型与训练目录绑定新动作/特征，旧 v6/v7 恢复、导出保持原契约并继续排除忠犬；不得手改标签。C 工作程序及规则摘要变化后使用新实验，旧数据需保留对应旧程序。实验分组包含技能组合；显式原七技能与省略配置归于同一家族，不能靠配置写法不同跨训练/测试划分。
