## 实现决定

用户已明确选择暂不限制重复对手：重复匹配仍按正常 Elo 规则计分，不增加每日次数上限、
收益衰减或重复对手匹配冷却。防刷策略不作为本次上线待办。

权威协调器放在 GMSV 的独立模块，空闲校验、名单保留和真实入战在同一线程执行。
这调整了讨论时“可先放 Go 网关”的模块位置，保持游戏能力和客户端范围不变。
`stoneage_ladder_core.c` 使用回调对接原生引擎，SQLite 单独存储积分和终局。
纯核心测试的 start 回调不是战斗引擎，不能用这些测试声称原生入战或重连已完成。

客户端请求走现有认证游戏连接的 S 扩展：

```text
LADDER|1|request_id|expected_revision|operation|argument
```

回复为 `LADDER|` 加 JSON；共享解析位于 `internal/ladder`，投影位于 `internal/aigame`。
线上姓名先传 GBK 十六进制，由共享 Go 层统一转 UTF-8。客户端不能提交积分、战力、
击杀统计、胜者或任意参赛名单。所有修改必须携带当前版本；未知执行结果保留原请求
ID 和版本，重试不能生成新请求。核心保存有限回执，过期回执由版本检查阻止重复修改。
回执增加 `request_hex`，共享层解码为 `request_wire`，按完整原请求关联；不能仅凭相同
请求 ID 取出另一操作的旧成功回执。历史结果查询标记 `result_lookup`，不覆盖当前比赛。

事件恢复由共享 `aigame.Session` 提供独立、最多 128 条的天梯状态记录。`stream` 是当前
登录连接/角色生命周期的标识；`cursor` 是服务器给该玩家的最后版本。服务器全局版本
可能因其他玩家而跳号，不能据跳号判断丢事件。重连、更换角色、缺少 stream、游标超前
或缓存截断时，返回 `gap=true` 和完整快照；调用者替换状态，随后使用新 stream/cursor。
超时保留最后快照，取消或连接关闭返回错误。当前不提供跨断线的历史逐条事件重放。

公式：人物基础预算为四项原始属性之和 / 100；等价属性点为
`(3*最大HP + 10*(攻击+防御+敏捷))/14`。人物取基础预算与装备后等价预算的较大值，
然后加上未分配点数，避免装备提高估值后漏算未分配属性；
登记宠物（含骑宠）去重后全部计入。按最大HP估值，实际伤害不改变匹配估值。
总战力误差为 `2*abs(A-B)/(A+B)`，双队等待均达到 0/30/90 秒时上限为 5%/8%/10%，
积分均值差上限 100/200/300；排序后个人误差上限 15%。这些参数仍需完整场景校准。
各模式初始1000，团队均值 Elo，K=32，同队同增减，对面相反，技术中断不计分。
