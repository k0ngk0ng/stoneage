# AI 生活活动目录

`goal.kind = "life"` 的活动池来自 `internal/airuntime`。没有在配置中指定
`goal.life.activities` 时，运行时使用下面 24 个预设；指定活动时仍会保留配置
中的顺序和字符串。每次生活决策只选择一个活动，活动本身不会绕过 MCP、任务
协调器或服务端确认。

目录通过以下导出函数读取：

```go
func ListLifeActivityPresets() []LifeActivityPreset
func LookupLifeActivityPreset(kind string) (LifeActivityPreset, bool)
```

`LifeActivityPreset` 的 `Description` 是执行范围，`Completion` 是完成条件，
`Fallback` 是能力或前提不足时的退化路径。`ListLifeActivityPresets` 返回可修改
的副本；修改返回值不会改变进程中的默认目录。

| kind | 名称 | 执行内容 | 完成条件 |
| --- | --- | --- | --- |
| `idle` | 发呆 | 观察必要状态后原地等待，不移动、发言或交易。 | 确认无需操作并等到下一次决策边界。 |
| `rest` | 休息 | 确认角色和宠物状态，在没有必须事项时原地休息。 | 角色可等待，且没有未经确认的写入。 |
| `observe` | 观察世界 | 用 `game_observe` 查看地图、人物、战斗、人物/宠物、背包和任务相关状态。 | 收到并核对当前服务端观察；缺失字段保持未知。 |
| `status-check` | 状态检查 | 用 `game_observe` 重点查看 HP/MP、经验、属性点、宠物状态、背包和运行中的任务。 | 已核对可用状态，并标明未知字段。 |
| `wander` | 闲逛 | 只在当前观察和已验证资料提供安全路线时，在已知区域短途移动。 | 后续观察确认目标，或确认无路线并转为观察/休息。 |
| `village-explore` | 村内探索 | 依据当前观察到的位置/对象和已验证路线探索，不猜坐标。 | 观察确认到达已知目标，或保留路线缺口。 |
| `village-npc` | 查看村内人物 | 查看当前可见 NPC；只有目标、位置和动作契约都明确时才考虑对话/窗口。 | 可见人物及前提已记录，结果由回执/观察确认。 |
| `nearby-people` | 观察附近玩家 | 查看当前可见人物、队伍和聊天，区分临时对象与持久身份。 | 社交上下文已读取；未知身份保持未知。 |
| `chat` | 聊天 | 有自然对话且确实有内容时才用 `game_action kind=chat` 回复。 | 回执和后续观察已核对，或确认无需发言。 |
| `chat-nearby` | 结识附近玩家 | 结合人格和真实处境自然打招呼、询问近况、分享见闻或回应已有话题；不反复搭话。 | 回复由回执/观察确认，或保持安静。 |
| `mail-check` | 查看邮件联系人 | 用 `game_action kind=mail, command=list` 读取当前地址簿。 | 查询同一回执 handle，确认请求后的新完整地址簿已收到；缓存的 `AddressBookKnown` 不算本次完成。 |
| `mail-contact` | 记录附近联系人 | 当前位置有明确玩家且有自然理由时，用 `mail add` 交换名片。 | 地址簿后续观察确认变化；提交不等于成功。 |
| `mail-send` | 发送必要邮件 | 仅向当前观察确认的地址簿槽位发送有明确目的的普通邮件。 | 发送回执及后续观察已核对；槽位不代表永久身份。 |
| `pet-care` | 照看宠物 | 查看稳定身份、等级、HP/MP、存活、出战和骑乘状态；已有审核任务负责恢复时只查询其状态，本活动不假定独立治疗工具。 | 宠物状态已确认；已有任务须由状态和观察确认。 |
| `pet-review` | 陪伴与检查宠物 | 查看宠物名称、等级、经验、技能及出战/待机状态；不强行切换或战斗。 | 宠物列表和需要关注的变化已确认。 |
| `inventory-review` | 查看背包 | 查看已知背包槽位、模板和容量，不凭名称猜效果。 | 已确认背包已知性、槽位和容量。 |
| `inventory-sort` | 整理背包 | 仅按明确槽位映射使用 `item move`，保留任务和恢复资源。 | 后续观察确认槽位变化且物品未丢失。 |
| `memory-recall` | 回顾记忆 | 用 `game_memory_list` 阅读私有笔记，并与当前观察对照。 | 相关笔记已阅读，过期内容标记为需重新观察。 |
| `memory-plan` | 整理计划 | 用 `game_memory_write` 保存明确的未完成事项、偏好或下一步意图。 | 写入结果或重新读取确认 key/text。 |
| `schedule-review` | 回顾定时计划 | 用 `game_schedule_list` 查看未来和到期提醒，区分投递与游戏完成。 | 列表已读取并避免重复动作。 |
| `schedule-reminder` | 建立定时提醒 | 对明确未来意图创建有界提醒，使用明确时间、提示和幂等 key。 | 返回的 schedule ID、时间和状态已确认。 |
| `stat-allocation` | 分配成长点 | 仅在 `flags[build:allocation_allowed]`、`own_progress[stat_points]` 和 `build_next_stat` 都已知且满足条件时，一次分配一点并观察。 | 服务端确认属性点或属性变化；未知结果不重试。 |
| `leveling` | 练级 | 仅继续 profile 已配置且知识库已验证、有边界的练级目标。 | `game_task_status` 和观察确认达成、暂停或失败。 |
| `quest` | 已验证任务 | 先查已验证知识和前提，再启动审核任务，不试错坐标或 NPC。 | `game_task_status` 返回权威完成条件和证据。 |

所有 game_action 游戏写操作都必须使用最新的观察 revision，并核对对应服务端回执或后续观察；记忆和定时工具使用各自的参数，不附加游戏 revision。公屏发言和普通邮件没有可靠发送方回执时保留送达未知，不重发、不无限轮询，但允许结束本次通信活动并继续无关生活活动。
没有路线、目标、恢复能力、物品、联系人、对话语境或其他必要前提时，活动退化为
只读观察或休息。生活目录不会随机要求玩家发言、加联系人、寄信、交易或战斗，
也不会把模型文字、旧笔记、地址簿槽位或一次提交当作持久身份和完成证明。

旧配置中的 `idle`、`rest`、`wander`、`chat`、`leveling` 和 `quest` 继续有效。
当前活动池最多 32 项；目录中的短别名只用于兼容查找，配置中的原字符串会保留。
