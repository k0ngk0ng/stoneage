# 2.5 指令/协议移植审计

审计基准是 `vendor/upstream/code_sa_client` 的正式（非 `_DEBUG`）代码、
`server/legacy/source/2.5/gmsv` 的协议头，以及网页运行时的实际调用点。

## 结论

* 本地键盘行为：**39/39**。包括 Enter、Backspace、Delete、Tab、↑/↓、F1–F8、
  Esc、任务栏 Ctrl 组合键、13 个动作快捷键、F5、Alt+Enter 和 F12。
* 2.5 协议编码/解码：**56/56**。网页 `CLIENT_FIELDS` 与 Go bridge 的字段数量、
  类型和编号由 `protocol_test.js` 逐项校验；其中 50 个来自保存的
  `LSSPROTO_CLI.H`，另外 6 个是当前 2.5 bridge 使用的兼容入口。
* 聊天服务端指令：**不在浏览器重复解析**。普通聊天、`[...]` 和 `/...` 内容均按
  原版包装成 `TK(P|text)`，由 2.5 GMSV 的 `CHAR_cmtbl` 按权限处理（当前构建的精确
  行数、别名和处理函数见下方统计；条件编译项会随服务端构建开关变化）。

## 本轮“同类指令”核对结果

这里把“网页端本地指令”和“服务器收到的聊天命令”分开统计。服务器命令不应该再
复制一份浏览器解析器，否则会绕过 2.5 GMSV 的权限、宏开关和目标校验。

| 范围 | 原版数量 | 网页状态 | 是否算遗漏 |
| --- | ---: | --- | --- |
| 2.5 正式客户端本地键盘（聊天、任务栏、动作、画面控制） | 39 | 39/39 | **0** |
| 2.5 GMSV `CHAR_cmtbl`（含 5 个内部处理器的中英文别名） | 183 表项、182 个别名、94 个处理函数 | 全部原文走 `TK(P|...)`，由服务端按权限处理 | **0** |
| 2.5 表外聊天入口（`/go`、`/gg`、`:` 频道、VIP/pub back-door、13 个文字动作） | 5 类 | 全部原文走 `TK(P|...)` | **0** |
| 2.5 客户端 `_DEBUG` 本地测试命令（`[battlein]`、`[battleout]`） | 2 | 有意不放进网页 | 不属于普通玩家功能 |
| 8.5 `_STONDEBUG_/_THEATER` 扩展（`scenery`、`movescreen`、`playnpc`、`[cary encountoff]`、`[cary encounton]`、`[battlein]`、`[battleout]`、`send <raw packet>`） | 8 | 有意不放进 2.5 网页 | 不属于 2.5 功能 |

因此，按“2.5 普通玩家可玩的聊天/本地指令”统计，当前确认的遗漏是 **0 项**；按
“所有调试命令也要搬过来”统计则有 **2 个 2.5 调试命令 + 8 个 8.5 `_STONDEBUG_`
扩展命令**被明确排除。这些命令不能算网页缺功能，也不应为了数量把 8.5 协议带进
2.5。

8.5 的 `_CHATROOMPROTOCOL`/`_FRIENDCHANNEL`/`_TELLCHANNEL` 也只在 8.5 的
`CHATROOM` 扩展协议中出现；2.5 `LSSPROTO_CLI.H` 和 GMSV 没有对应入口，因此这组
聊天室/好友/密语封包不属于“网页漏移植”。2.5 可用的家族频道切换（消息首字符 `:`）、
`/go`、`/gg`、VIP 语法和 13 个文字动作仍由现有 `TK(P|...)` 路径交给 GMSV。

8.5 还存在两个容易混淆的条件分支：`_CHAR_MANOR_DEBUG` 下的 `.光环` 在该源码的
`version.h` 中是注释掉的宏，当前构建不可用；`_DIEJIA_` 的物品栏按钮会发送
`/叠加`，这是 8.5 专属 UI/服务端扩展，不是 2.5 普通玩家指令，网页故意不发送。

### 当前 2.5 构建的精确数量

用 `server/legacy/source/2.5/gmsv/include/version.h` 的实际宏做预处理后，当前构建的
`CHAR_cmtbl` 是 **183 个表项**、**182 个名称**（唯一重复名称是兼容用的 `dp` 表项），
对应 **94 个处理函数**。其中 5 个内部调试/管理处理器（`battlein`、`battleout`、
`debug`、`crash`、`shutdown`）各有中英文别名，共 **10 个内部表项/10 个名称**；排除
它们后剩余 **173 个表项、172 个别名、89 个处理函数**。所有表项均为 `isdebug=TRUE`，
即 GM/调试权限指令，不是普通玩家 UI 要在浏览器本地复制的命令解析器。源文件中被
`#ifdef` 排除的条件版本不计入当前 2.5 可用指令。

表外仍有 2.5 GMSV 的 5 类聊天入口：`/go`、`/gg`、以 `:` 开头的家族频道切换、
VIP back-door/show 语法，以及 13 个文字触发动作。网页对它们和普通文字使用同一条
`TK(P|text)` 原始通道，服务端会按当前配置、账号权限和宏开关决定是否执行；浏览器端
没有漏掉其中任何一类。冒号切换不是浏览器本地命令，服务端会在 `CHAR_Talk()` 中读取
并更新当前家族频道，因此网页不应自行改写或拦截它。

## 清空聊天

原版没有 `/clear` 文本指令。`MAIN.CPP` 收到 `VK_DELETE` 后直接调用
`ClearChatBuffer()`，只清空屏幕上的聊天行，不清除发送历史和当前草稿。
网页支持相同的 Delete（macOS 用 Cmd+Backspace），并额外提供本地清屏别名
`/clear`、`/cls`、`/clearchat`、`/clear-chat`、`/clear_chat`、`/clear chat`、
`/clearlog`、`/clear-chat-log`、`/清屏`、`/清空聊天`、`/清空聊天记录`、
`/清除聊天`、`/清除聊天记录`，以及不带斜杠的严格同义词；手机输入法的全角斜杠/字母也会规范化。这些别名不会
发送给服务器。

另有一个容易混淆的本地编辑快捷键：`Shift+Backspace` 清空当前获得焦点的
`STR_BUFFER`（聊天、邮件、称号/对话等），它来自 8.5 `_SA_VERSION_25` 的兼容
`WM_KEYDOWN/VK_BACK` 分支，不是聊天指令，也不会产生任何服务端封包；它与
`Delete` 清屏分别处理。

## 目前的移植数量

按 `LSSPROTO_CLI.H` 的 50 个正式客户端发送入口，加上本地 2.5 GMSV 实际使用的 6 个
兼容入口（共 56 个 schema）核对后：**56/56 可编码**。正式客户端入口中，网页已有
实际游戏路径的 **44/50**；剩余 6 个都是原版也没有普通玩家调用，或必须由服务端/管理端
处理的入口，并非漏移植。需要的普通游玩和生命周期路径均已有网页调用；另外有 6 个
仅保留在协议控制台/兼容层的入口：

| 入口 | 处理 | 说明 |
| --- | --- | --- |
| `w` | 有意不发送 | 无校验移动仅用于特殊客户端模式；网页普通行走使用服务端校验的 `W`。 |
| `EN` | 服务端自动路径 | 2.5 GMSV 在接受 `W` 后自行掷遇敌；网页再发会重复计算。 |
| `BU` | 无普通玩家调用 | 只在战斗结束等服务端回包路径出现，网页不主动伪造。 |
| `SKD` | 无正式调用点 | 保存的 2.5 客户端没有实际发送调用。 |
| `DT` | 无正式调用点 | 角色称号删除/兼容入口，当前 2.5 普通游玩没有可达按钮。 |
| `Shutdown` | 管理接口 | 只允许管理端使用，不属于玩家网页。 |

`PMSG`（宠物邮件）和场景宠物技能 `PS` 均已有专用网页入口；普通 `/...`、`[...]`
内容仍原样封装成 `TK(P|...)` 交给 GMSV，不在浏览器复制服务端命令解析器。

## 专用网页入口补齐情况

以下不是“协议没移植”：它们都已经能由协议控制台编码并经过 bridge 校验；只是没有
单独的玩家 UI，或原版正式客户端没有可达调用点。

| 入口 | 状态 | 原因 |
| --- | --- | --- |
| `PMSG` 宠物邮件 | **已补齐** | 通讯录寄信窗口可切换到 PET MAIL，按原版 `PMSG(index, petindex, itemindex, message, color)` 发送；宠物和道具附件均可循环选择。 |
| `PS` 场景宠物技能 | **已补齐** | 宠物技能页点击非战斗技能发送 `PS(havepetindex, havepetskill, 0, "")`；战斗技能仍走原版 `B/W` 回合指令，避免越过战斗状态机。 |
| `w` 无校验移动 | 有意未走专用入口 | 原版仅在无校验移动模式下使用；网页的普通行走由 2.5 服务端校验，固定发送 `W`，避免重复/绕过校验。 |
| `EN` 遇敌请求 | 有意不发送 | 当前 2.5 GMSV 在接受 `W` 后自行掷遇敌概率；网页再发 `EN` 会重复计算。 |
| `SP`、`TD`、`FM`、`PETST`、`MA`、`SPET` | 2.5 bridge 兼容入口 | 这些是本地 GMSV/扩展回包所需的 schema，不属于保存的 2.5 `LSSPROTO_CLI.H` 50 个正式发送入口；有对应网页路径的入口仍按原协议使用。 |

因此目前没有确认缺失的正式 2.5 玩家协议入口；按“原版可达的普通玩家功能”统计为
**0 项遗漏**。聊天清屏也不是隐藏的文字指令。
调试命令（如 `[battlein]`、`[battleout]`、`movescreen`、`playnpc`）不属于正式可玩功能。

### 不计入统计的客户端残留

* `NETPROC.CPP` 仍留有 `lssproto_ChangePasswd_send/recv` 的旧密码修改代码，但该函数
  没有出现在正式 `LSSPROTO_CLI.H`，当前 2.5 GMSV 也没有对应的接收入口，因此网页不
  会伪造这个封包，也没有把它算作 2.5 玩家功能遗漏。
* `PROCESS.CPP` 声明了 `kakushi_command()`，但归档源码没有实现；它只属于隐藏/调试
  构建路径，和 `_DEBUG` 下的 `[battlein]` 等测试命令一样不进入正式网页。
* 8.5 `_STONDEBUG_` 的 `send <raw packet>` 是客户端调试注入通道；网页没有对应的
  `sendDataToServer()` 后门，普通聊天仍只允许经过协议 bridge 的已知函数。
* 8.5 `_CHAR_MANOR_DEBUG` 的 `.光环` 仅在该调试宏打开时存在，而随附 `version.h`
  明确将宏注释掉；它不属于可用版本，也不计为遗漏。
* 8.5 `_DIEJIA_` 物品栏按钮会直接发送 `/叠加`。这是 8.5 专属的服务端扩展；2.5
  GMSV 的 `CHAR_cmtbl` 和聊天处理路径没有对应命令，因此网页不会伪造这个文本封包，
  也不把它计入 2.5 普通玩家功能的遗漏。
