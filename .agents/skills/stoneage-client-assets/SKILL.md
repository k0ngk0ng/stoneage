# StoneAge 客户端资源导入

这是项目级技能。以下命令从仓库根目录执行；先阅读根目录 `AGENTS.md` 的原版参考和资源保留规则。

## 工具与输入

- 当前客户端为 `client/web`。共享解码器是 `tools/asset_cooker.py`，原版 Web 资源提取入口是 `tools/extract-legacy-web-assets.py`。
- `scripts/import-white-tiger-assets.py` 是已验证的白虎专用导入器；导入白虎时阅读 [references/white-tiger.md](references/white-tiger.md)。不要把其角色编号、动作集合或真彩色格式断言直接套用到其他资源。
- 工具保留在仓库原位置，由技能调用；修改解码逻辑时更新公共实现，不在技能中复制一份。
- 8.5 行为优先参考 `~/Sources/github.com/anson1788/stoneage` 完整目录。功能支持与资源存在分别核查：源码、服务端归档、Lua 和配置用于确认行为，实际 BIN 索引与动画帧用于确认素材。
- `runtime/legacy-client` 是已保存的旧客户端数据来源；`vendor/client-resources/` 保存长期保留的下载原件和来源清单。输入只读，临时分析和导入候选包写入本项目 `build/`。

## 导入流程

1. 确认资源组、目标图号及客户端版本，读取该组来源记录和 SHA-256 清单。复用已经验证的解码索引，不重新猜测偏移。缺少匹配索引或原件时报告具体缺项。
2. 核对 ADRN 与 REAL 同组且记录边界、尺寸、RD 头一致；核对 SPRADRN 与 SPR 的角色、方向、动作及帧引用。区分索引色资源与真彩色资源，依据实际格式选择解码路径。
3. 保留原始帧定位、动画时序、透明度和事件字段。历史输出字段 `frame_ms` 在白虎包中表示原生动画 tick，不应仅凭字段名换算为毫秒。
4. 用对应工具在新的 `build/` 子目录生成候选包，记录源文件哈希和源图号到目标图号的映射。先用 `--help` 查看实际参数；Web 提取器运行前必须显式指定 `--output`，避免默认写入现有资源包。
5. 检查目标图号是否冲突、各方向和动作是否齐全、每帧图片是否存在。对站立、行走和战斗关键帧进行视觉检查，确认颜色、透明背景、脚底定位及动作事件正常。
6. 用户要求接入 Web 时，再按现有清单结构合并已验证的候选内容，保留不相关条目；检查完整动画清单与场景启动精简清单的一致性。生成候选包本身不等于已完成客户端接入。

## 验证与交付

- 公共解码器或 Web 提取逻辑有改动时，运行 `PYTHONDONTWRITEBYTECODE=1 python3 tools/extract-legacy-web-assets_test.py`；这依赖本地原版数据及现有 Web 资源，不覆盖所有新导入内容。
- 结合本次素材检查生成结果及来源记录，报告具体输入、输出、图号映射、覆盖范围和未完成的验证。
- CDN 路径和本地缓存遵守 `AGENTS.md`；导入不自动上传资源、部署、改生产配置或删除原件。发布操作按用户当次任务范围及项目发版流程执行。
