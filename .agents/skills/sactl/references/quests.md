# 自动任务（v0.2.18）

仅用于已授权的当前角色。`quest` 复用 HTTP 游戏会话与 Web 的确定性执行器、控制权、预算和持久化检查点；不调用本地 learned/LLM，不使用用户提交的原始动作计划。

```sh
sactl quest --help
sactl quest list
sactl quest preview <task-id> --include-dependencies
sactl quest start <task-id> --include-dependencies
sactl quest status --json
sactl quest pause
sactl quest resume
sactl quest cancel
```

`<task-id>` 必须来自当前目录；先检查要求和审核阻碍。示例不表示任何特定任务已上线。preview/start 的参数放在任务 ID 后：`--maximum-seconds` 默认 1800，`--maximum-deaths`、`--maximum-spend`、`--reserve` 默认 0。需要宠物的任务用 `--pet <稳定身份>` 明确选择，不能猜测或用槽位代替稳定身份。预览不会授权支出，启动时须再次带上所需参数。

启动返回后，会话保持连接时继续执行。关闭登录会话会中断执行，不能把退出 CLI 单次命令和登出混淆。断线后重新登录同账号、角色与线路，先看 status，再显式 resume 或 cancel 服务端提供的恢复任务；不自动重发未确认交付。任务预览通过也不意味着已执行，只有 `automation_task.status=confirmed` 且状态为 completed 才是服务端任务执行器确认完成。步骤进度的数字是已完成数量，状态为 paused/failed/unknown 时报告原因。

普通输出便于阅读，Agent 使用 `--json`：状态包含 control、automation_active、automation_mode、automation_task（句柄、结果、原因和 progress），以及 automation_recovery。最终结果在当前会话内保留，启动下一次自动化会替换它；断线后的恢复以持久化检查点为准。

当前仅 HTTP 会话支持。直连 TCP、旧客户端后台或不支持对应接口的旧 Web 返回错误，不回退到原始协议或跳过参数执行。自动任务与本地 auto-battle 互斥，先停止已有自动战斗。请求报错/超时后先查 status；不得循环重试 start、交付或取消。

v0.2.18 的交宠保护：共享 NPC 执行器只在已审核的交付规则下，根据实时槽位顺序、种类、等级、事件标记核对确切稳定身份，再确认交付。`SpeciesIDKnown` 和 `EventFlagKnown` 缺失时不可推断；种类与数量符合也不代表可以消耗玩家原有宠物。当前服务端在 235/YES 后还有 430/OK 确认页，保护须绑定实际扣宠的最终按钮；不能收到“恭喜完成”窗口就宣称已交付。

共享执行器新增有次数/回合上限的 `pet.capture`，只处理已经进入的独行 PvE。它使用关联 BCAP 观察，拒绝可能消耗道具的整场遭遇，宠物等待；可配置先削弱高血量目标，再尝试捕获，普通攻击仍受总回合上限限制。捕获指令写入成功不算成功，必须结束战斗并刷新确认新增稳定身份。不会丢弃原有宠物腾位置，也不会重发结果不明的操作。

`pet.collect` 已接入任务检查点：保留全部原有宠物身份，按种类和等级选遇敌区域，逐次保存新捕获身份。`pet.deliver` 从同一计划较早的已确认采集步骤取得身份集合，在最终提交前保存奖励/库存基线，之后同时核对金币到账、确切物品扣除及交宠结果。恢复只接受已证明的空闲边界，或已经完全符合交付回执的结果；未知战斗、移动和用药结果不自动重发。

采集可使用经审核的自有补血物品；总恢复次数有上限，实际 HP 未达到要求就不继续进入遭遇区。缺药时需补给后恢复，不自动购买未授权物品。带金币奖励的交宠需要新服务端的 `AI.GoldLimitKnown/GoldLimit`；达到金币上限（包括刚好相等）会在确认前拒绝。旧服务端不提供该字段时明确停止，不能按转生次数猜限额。

源码新增内置任务 `marinas-pet-commission-a`（玛丽娜丝村宠物委托 A）。需要服务端显式配置匹配的任务/NPC/补给目录及新版原生程序；未配置时不能直接假定线上可用。对已配置的开发环境：

```sh
sactl quest list
sactl quest preview marinas-pet-commission-a --maximum-spend 146
sactl quest start marinas-pet-commission-a --maximum-spend 146
sactl quest status
```

该任务自动采集四只新宠，不用传 `--pet`；此参数仍只用于要求明确选择一只已有宠物的其他任务。开始前须独行、存活，保留四个空宠位、九个空背包格、146 石币及奖励容量。已有同种宠物应由玩家先存放，其他本村委托书也须先移走，不能替玩家擅自处理。采集和交付始终保护原有身份。缺条件时先处理 preview 的提示，不反复 start。

任务运行期间只读查询及心跳保持可用；主动操作仍受控制权限制。HTTP 会话会保留任务返回的控制版本，用于随后恢复手动操作。跨地图事件必须取得匹配序号的服务器确认；缺回执不重发传送。最终完成仍以精确交付回执为准，不把本地验收或预览成功当成完整任务集合已经上线。

其他三村的宠物委托 A 仍是禁用草稿：萨姆吉尔/卡鲁它那最低二级、加加最低五级只是已核验路线的准备要求，不表示任务已验证或允许启动。不得修改审核标记绕过限制，也不得在 preview 拒绝时反复 start。自然练级准备尚未完成端到端验收；其单次寻路/恢复也受总时间与无进度预算限制，超时后检查状态并处理原因。

开发版导航按原版重叠区域优先级寻找实际生效且可达的目标格，不再只试区域中心和角点；不会降低等级或生命安全限制。共享补给执行器等待新收到且尚未提交的商店窗口，忽略上次访问留下的已提交窗口；未知购买结果仍停止核验，不重复扣款。
